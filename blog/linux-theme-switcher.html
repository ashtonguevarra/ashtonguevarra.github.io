Linux / Bash / Hyprland / Automation

Everything Else Follows.

How I got tired of manually recoloring my Linux rice and built a wallpaper-driven theme switcher instead.

I’ve been Linux ricing for quite a while now.

And as much as I love it, there has always been one part of the process that quietly drives me insane.

You find the perfect wallpaper.

You set it.

Then you look at your terminal.

Wrong colors.

Waybar? Wrong colors.

Rofi? Still living in the previous rice.

So you open every config file individually, start changing hex codes, realize you don't actually know the exact shade you want, open some color-picker website, steal a palette from your own wallpaper, copy the values back into your configs, reload everything...

And then, eventually, your desktop is beautiful again.

Until you decide to change the wallpaper.

Then you do it all over again.

At some point I started wondering:

What if I never had to do this manually again?

And that's how a small weekend project turned into a theme switcher for my entire Linux system.

One Wallpaper to Rule Them All

The idea was simple.

I wanted to be able to choose a wallpaper and have everything else change with it.

No hunting for colors.

No opening five different config files.

No manually trying to make my terminal match my Waybar, which needs to match Rofi, which needs to match Hyprland, which needs to match the wallpaper.

Just:

Pick a wallpaper.

And let the system figure out the rest.

My switcher now automatically changes:

  • → the wallpaper
  • → the terminal colorscheme
  • → Waybar
  • → Rofi
  • → parts of my Hyprland configuration

The entire desktop derives its colors from the image I choose.

One command. One wallpaper. One completely different rice.

Before / After

Same desktop. Different wallpaper. Different theme.

The Ingredients

I didn't need to reinvent everything from scratch. A few existing Linux tools already did individual pieces of what I wanted.

The main ones were pywal16, AWWW, and fzf.

01 / fzf

Gives me an interactive terminal menu for choosing the wallpaper.

02 / AWWW

Handles actually setting the wallpaper, including the transition animation.

03 / pywal16

Analyzes the selected wallpaper and generates a matching color palette from it.

So instead of me staring at an image and thinking,

"Is that #7393B3? Maybe #6082B6?"

the computer does it for me.

As it should.

Setup

pywal16 + AWWW + fzf doing the heavy lifting.

Wallpaper selection, color generation, and desktop refresh all tied together.

How It Works

The entire thing is tied together with a Bash script.

The flow looks something like this:

Run script → check AWWW → find wallpapers → open fzf → choose wallpaper → animate wallpaper change → generate colors → refresh the rest of the desktop.

The Script

One Bash script connects every part of the process.

AWWW handles the wallpaper while pywal16 handles the generated palette.

When the script starts, it first checks whether awww-daemon is running and starts it if necessary.

It then searches my wallpaper directory and pipes the available images into fzf, giving me a simple interactive menu right inside the terminal.

I choose one.

AWWW applies it with an animation.

Then pywal16 analyzes that image and generates a new color palette.

And that's where things get interesting.

Making Everything Listen

Generating the colors was actually the easy part.

The harder question was:

How do I make the rest of my desktop use them?

By default, having pywal generate a beautiful palette doesn't magically convince every program on my computer to use it.

Each component still has its own configuration.

So instead of hardcoding colors into those configs, I changed them to reference colors generated by pywal.

Hyprland

Generated colors can be referenced for things such as my window borders.

Waybar

Its style.css pulls its background and foreground colors from the generated theme.

Rofi

Rofi does the same through its .rasi configuration and launcher theme.

Configuration

The colors themselves aren't permanent anymore.

The configs reference whatever palette the current wallpaper generates.

The important difference is that the colors themselves are no longer really the permanent part of my rice.

The references are.

My configs essentially say:

"Whatever colors the current wallpaper generated, use those."

So when the wallpaper changes, pywal generates a new palette, the relevant configs pick up those colors, and the desktop refreshes around them.

The wallpaper becomes the source of truth.

Now I Can Be Indecisive in Peace

And that's my favorite part of this project.

I can completely change the mood of my desktop without spending the next half hour rebuilding the rice around it.

Dark wallpaper? The system follows.

Something warm? The system follows.

Blue? Purple? Muted? Bright? The system follows.

What used to be a tiny ritual of opening config files, finding color values, copying hex codes and reloading applications has been reduced to choosing an image.

There's something deeply satisfying about that.

Not necessarily because this was some enormous or revolutionary project. It wasn't.

It was just a problem that annoyed me.

And I think those are sometimes the best projects to build.

You notice a tiny inconvenience you've accepted for months. You finally get tired enough to do something about it. You write a script, break a few things, read documentation, connect tools that were never necessarily designed as one system...

And eventually the computer starts behaving the way you wanted it to behave.

That's one of the things I've always loved about Linux.

You can spend hours customizing something nobody else would care about.

You can obsess over the color of a border.

You can write an entire script because you're too lazy to change a few config files manually.

And somehow, by being lazy enough, you end up learning how your system actually works.

So now when I get bored of my rice, I don't open a color picker.

I don't start digging through config files.

I don't rebuild my theme.

I pick another wallpaper.

Everything else follows.
